# 演示视频脚本（3 分钟 · C 负责）

> 结构：痛点 → 方案 → 演示 → 数据 → 价值。
> 拍法：**录屏 + 配音**，不实拍。理由：现场不可能真去困人，录屏可控、可重录、零风险。
> 工具：OBS / Windows 录屏（Win+G）+ 剪映。旁白用手机录音也比笔记本麦克风好。

## 一、痛点（0:00–0:35）

**画面**：电梯门关闭的镜头（可用免费素材），叠一行大字："如果这时候停电，里面的人怎么办？"

**旁白**：
> 全国在用电梯超过一千万台，每天都有困人故障发生。
> 现有的电梯物联网只采集一件事——**机器有没有故障**。
> 但真正致命的是另一种情况：机器没报故障，人被关在里面，按了警铃没人听见，甚至已经倒地不起。
> 我们想回答的问题很简单：**轿厢里那个人，现在怎么样？**

## 二、方案（0:35–1:05）

**画面**：架构图（`TECH_DOC.md` §2），从"视频帧"开始，逐段高亮到"Decision"。

**旁白**：
> 我们不加布线、不换电梯，只用轿厢里已有的摄像头，加一路电梯运行信号。
> 视觉回答四个问题：有几个人、有没有人倒地、有没有人贴门、拥挤度多少。
> IMU 判断电梯自己是不是不对劲：急停、异常振动。
> 两路信号进状态机，加上"滞留时长"这一个最关键的判据——超过 180 秒，才算困人。
> 最后输出的不是一个是非题，而是**楼层、人数、紧急度、以及为什么这么判**。

## 三、演示（1:05–2:10）★ 核心

**画面**：左侧小窗放演示视频，右侧全屏看板。看板顶部四个数字卡，下方告警列表。

**操作**：终端执行
```bash
python -m service.main
```
（已提前启动则省略）另一终端：
```bash
python scripts/play_case.py --case demo_faint
```

**旁白（边看边说）**：
> 这是我们的监控看板。现在回放一段"有人倒地"的演示数据。
> （告警弹出）**三楼，两人，紧急度三级——红框，带脉冲。**
> 下面这四行就是判定理由：滞留 412 秒、超过 180 秒阈值；门是关的；倒地概率 0.87；IMU 急停 0.92。
> **每一条都能追到具体数值，不是"系统认为"这种空话。**
> 值班人员点"确认处置"，这条告警进历史，平均响应时长自动更新。
> （切窗口）现在我把环境变量改成 sqlite 加内存——模拟答辩现场断网——**代码一行没改，看板照样弹告警。**

## 四、数据（2:10–2:40）

**画面**：`MODEL_CARD.md` 的指标表 + 混淆矩阵 + 消融表。

**旁白**：
> 在自建的 XX 段测试样本上，困人识别召回率 XX%，误报率 XX%。
> 消融实验显示：去掉时长判据，误报上升 XX 个百分点；去掉 IMU，急停场景召回下降 XX。
> 端到端从视频帧到看板告警，延迟 XX 秒。
> 我们也清楚局限：夜间低照度下姿态估计会退化，这时系统会明确标记"关键点不可信"并降级到人数加时长判据，而不是硬判。

> ⏳ 以上数字由 B 在 D12 前提供，**没测出来就不念，不要编**。

## 五、价值（2:40–3:00）

**画面**：客户画像三栏 + 一句话金句。

**旁白**：
> 对物业，它是责任兜底；对维保单位，它是差异化服务；对监管平台，它是实时的民生数据。
> 因为不改硬件，一台摄像头就能覆盖一部电梯，复制成本极低。
> **我们不看电梯坏没坏，我们看人有没有出来。**

## 录制清单

- [ ] 服务先启动，`.env` 用 `sqlite + memory`（录屏时最稳）
- [ ] 浏览器全屏、缩放 125%（投影/视频里字更大）
- [ ] 演示数据用 `demo_faint`（效果最强烈），备选 `demo_trapped`
- [ ] 录屏分辨率 1920×1080，25fps 以上
- [ ] 旁白单独录，语速放慢，每句不超过 20 字
- [ ] 成片加字幕（剪映自动识别后人工校对）
- [ ] 导出 MP4 / H.264，文件小于 200MB

## 常见翻车点

| 问题 | 预防 |
|---|---|
| 录到一半告警被去重"吃掉" | 每次录前清库：删 `elevator.db` 后重启 |
| 看板显示"连接断开" | 确认服务窗口没关 |
| 视频与告警不同步 | `--speed 1`，先空跑一遍确认 |
| 旁白有杂音 | 手机贴近嘴 15cm，关空调 |
| 时间超了 | 先按 3 分钟剪，删掉所有形容词 |
