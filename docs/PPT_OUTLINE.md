# PPT 大纲（15 页 · C 统稿）

> 用法：每页按「一句话主张 → 页面元素 → 口播 30 秒」写。
> 状态标记：✅ 今晚就能定稿 ｜ ⏳A 等 A 的素材 ｜ ⏳B 等 B 的素材
> 原则：**一页一句话**。评委看 15 页只有 5 分钟注意力，字多必减分。

---

## P1 标题页 ✅
- **主张**：电梯困人主动预警 —— 从"机器故障"到"人的处境"
- **元素**：作品名、副标题、团队名、三人姓名、赛题名、日期
- **口播**：一句话定位，不念团队名单。

## P2 痛点 ✅
- **主张**：困人不是"机器坏了"，而是"人被困住了却没人知道"
- **元素**：3 个数字（电梯保有量 / 年均困人故障数 / 平均救援时长）+ 1 张电梯轿厢示意图
- **数据来源**：市场监管总局年度特种设备统计、地方 119 救援通报
- ⚠️ **答辩前必须核实数字并写清来源年份**，任务卡里的"1100 万台"要以官方最新统计为准
- **口播**：先讲一个具体场景（老人独自乘梯被困 40 分钟无人知晓），再说数字。

## P3 现有方案为什么不管用 ✅
- **主张**：现有电梯物联网只采"故障码"，不采"人在里面怎么样"
- **元素**：左右对比表 —— 现有方案 vs 我们的方案（采集对象 / 判断依据 / 盲区）
- **口播**：三类盲区 —— ① 有故障但没困人（误报）② 没故障码但人被困（漏报）③ 有人倒地无人按铃（最致命）

## P4 我们的创新 ⏳B
- **主张**：把"人的处境"变成可计算的信号
- **元素**：创新点 3 条（视觉为主 + IMU 为辅 / 时长累积的状态机 / 可解释 reason）+ 与现有方案差异图
- **交付**：B 提供 3 条创新点文案与差异对比
- **口播**：强调"传统场景的新突破"，落在赛题偏好的创新维度。

## P5 数据集与处理 ⏳A
- **主张**：数据从哪来、怎么标、怎么变成模型能吃的形状
- **元素**：数据来源表（公开数据集 + 自采）、标注方式、`VisionOut` 字段表、样本量
- **交付**：A 提供 + `data/DATA_DICT.md`
- **口播**：只讲"为什么这样处理"，不讲工具版本。

## P6 系统架构 ✅
- **主张**：云边协同，三通道解耦
- **元素**：架构图（见 `TECH_DOC.md` §2）—— 视频→YOLO-Pose→VisionOut→融合/状态机→Decision→FastAPI→RDS/Redis→看板
- **口播**：强调接口契约先行（`VisionOut` / `Decision` 两个结构体），三人可并行开发。

## P7 视觉感知 ⏳A
- **主张**：人数、倒地、贴门三个信号，全部可解释
- **元素**：带标注的截图/视频帧 2 张 + 判定公式（几何关系 + 时序滤波 + 阈值）+ 防误报设计
- **交付**：A 提供截图与公式
- **口播**：重点讲"防误报"——为什么弯腰捡东西不会被判成倒地。

## P8 决策与可解释 ⏳B
- **主张**：不是黑盒打分，而是能说出"为什么"
- **元素**：状态机状态转移图 + 一段真实 `Decision` JSON 的 `reason` 字段（**关键代码片段**）
- **交付**：B 提供状态机图与代码片段解读
- **口播**：念出 reason 那四行，说明每条都能追到具体数值 —— 这是可解释性的实证。

## P9 量化指标与消融 ⏳B
- **主张**：指标可复现，消融证明每个模块都有用
- **元素**：混淆矩阵 / 召回率-误报率 / 延迟（端到端秒数）/ 消融表（去 IMU、去贴门、去倒地各降多少）
- **交付**：B 提供 + `model/MODEL_CARD.md`
- **口播**：先给结论数字，再给一句"在 XX 场景下仍有局限"（诚实加分）。

## P10 华为云产品使用 ✅（需截图）
- **主张**：不是"假装上云"，是真用了三件套
- **元素**：RDS 实例截图、Redis 实例截图、ECS 部署截图、CodeArts 生成部署配置的截图 + 一张调用关系图
- **口播**：逐个说"这个服务解决了什么问题"，不要念配置参数。
- 📸 截图位：`docs/screenshots/`

## P11 昇腾适配（可选）⏳A
- **主张**：国产算力可迁移
- **元素**：ONNX 导出 → 昇腾推理的适配路径图 + 实测/说明
- **若未落地**：明确写"已完成 ONNX 导出与适配方案，真机验证待资源到位"，**不许含糊**

## P12 部署与双模式兜底 ✅
- **主张**：云上生产 / 离线兜底，任何网络环境都能演示
- **元素**：双模式切换表（rds+redis / sqlite+memory）+ 降级流程图 + 一句"改两行环境变量，代码零改动"
- **口播**：这是"技术架构完备且可行"最直接的证据。

## P13 商业模式 ✅（骨架）
- **主张**：卖给谁、怎么收费、为什么能规模化
- **元素**：客户画像（物业 / 电梯维保 / 保险 / 监管平台）、收费模式（按梯年费 / SaaS / 与维保分成）、复制路径（不改硬件 → 加装摄像头即可）
- **口播**：强调"零硬件改造"是规模化的关键。

## P14 团队 ✅
- **主张**：三人三条线，契约协作
- **元素**：三人照片 + 分工一句话 + 一句协作方法（接口契约先行、每日合并）
- **口播**：10 秒带过。

## P15 谢谢 / Q&A ✅
- **主张**：留一个记忆点
- **元素**：一句话金句 + 二维码/仓库地址（若开源）
- **金句候选**："我们不看电梯坏没坏，我们看人有没有出来。"

## 答辩必备的 5 个数字（提前背下来）

| 数字 | 含义 | 来源 |
|---|---|---|
| 电梯保有量 | 市场天花板 | 官方统计（答辩前核实） |
| 困人故障占比 | 痛点强度 | 地方监管通报 |
| 平均救援时长 | 现状基线 | 消防救援公开数据 |
